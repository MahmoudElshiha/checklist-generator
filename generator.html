How it works, and the source format

Workflow. Start with New, Open source or Import page. If your project has a checklists.config.json, load it with Project settings first — it adds your project's step labels and defaults. Edit the JSON on the left; the page on the right updates as you type, and anything wrong is listed under the editor. Name the file date first (2026-11-12-feature-manual-tests), then Download source into your sources folder and Download page into your pages folder. Your draft and project settings are kept in this browser.

Rules. Every text needs en and ar, and may contain HTML (<code>, <strong>…). Sections and checks are numbered for you — never type the numbers. Each check's key is what the browser saves the tick under: keep it when you reword a check. code blocks are plain text with a Copy button.

{
  "title":   { "en": "Feature Checks", "ar": "فحوصات الميزة" },
  "heading": { "en": "Feature — manual checks", "ar": "الميزة — الفحوصات اليدوية" },
  "intro":   { "en": "<p>What is tested and why.</p>", "ar": "<p>ما الذي يُختبر ولماذا.</p>" },
  "sections": [
    { "title": { "en": "Setup", "ar": "التجهيز" }, "items": [
      { "key": "setup-build",
        "title":  { "en": "The test server runs the latest build", "ar": "خادم الاختبار يعمل بآخر نسخة" },
        "steps":  [ { "where": "server", "en": "Run <code>make deploy</code>.", "ar": "شغّل <code>make deploy</code>." } ],
        "code":   [ "make deploy" ],
        "expect": [ { "en": "It finishes without errors.", "ar": "ينتهي دون أخطاء." } ] }
    ] }
  ]
}
